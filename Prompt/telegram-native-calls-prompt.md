# 接通 Nyarugram 原 Telegram 通话

请在现有 Botgram 客户端和 Botgram.Backend 后端中实现 Telegram 应用内网络通话，保留原 Telegram 通话页面、控制器和媒体引擎，并交付可以验证的完整呼叫链路。

## 项目与现状

- 客户端位于 `W:\Work\Botgram`，后端位于同级 `W:\Work\Botgram.Backend`。
- 开始前阅读两个仓库的 `AGENTS.md`，以及客户端的 `Botgram.Android.md`、`Botgram.GID.md`、`Botgram.Chinese.md`。涉及运行服务时阅读后端 `DEPLOYMENT.md`。
- 根据当前源码、配置和进程记录核实状态。保留已有用户修改，历史报告和构建记录按各自版本理解。
- 当前绑定账号使用 Bearer 认证的 typed Protobuf HTTP RPC，具备独立事件提示和差分机制。接入方案须适配这套通信方式。
- 后端已有独立 REST 通话状态及信令，原 Android `phone.*` 通话流程仍待接通。前端根据用户完整资料中的通话能力字段显示按钮，当前能力字段未启用。
- 用户使用 Gram ID。所有呼叫对象通过稳定账号 UUID 和 TL ID 关联，Gram ID 的 TL `phone` 兼容字段只能用于应用内身份展示和解析。

## 目标与交付顺序

1. 首先完成原 Telegram 一对一语音及视频通话，从双方原聊天页和资料页发起，覆盖响铃、接听、拒绝、取消、挂断及真实双向媒体。
2. 单独审计群组及频道通话，列出依赖的 `phone.*` 方法、更新类型、成员管理和媒体服务。分阶段推进群组通话，并分别报告验收结果。
3. 对所有尚未完成的通话类型、方法、网络路径和设备场景记录明确状态。一对一完成时，报告整个通话任务的剩余工作。

## 实现要求

### 原页面与能力声明

- 复用原聊天页、个人资料页、来电界面、通话界面、前台服务和通知组件。
- 通过真实可用能力和隐私规则控制语音、视频及群通话入口。能力查询失败、对方不支持和隐私限制应有明确反馈。
- 完成所声明能力的完整链路后再启用相应能力字段，并检查新旧资料缓存和其他会话的刷新。
- 网络、加密重计算和文件操作放在后台，正确处理页面销毁、请求取消、迟到回调、退出和账号切换。

### 呼叫状态与权限

- 持久化呼叫参与者、会话关联、稳定呼叫标识和必要状态，按原客户端消费方式映射。
- 实现发起、振铃、接听、确认、拒绝、主叫取消、挂断、忙线和超时。
- 验证参与者权限及每个状态迁移，处理重复请求、乱序更新、同时接听、多设备接听、相互呼叫和挂断竞争。
- 成功响应代表所需状态已经持久化。维护幂等性、事务回滚和服务重启恢复。
- 执行黑名单、呼叫隐私及 P2P 隐私设置。被限制的呼叫在服务端拒绝。
- 登录过期、退出或切换账号后隔离旧呼叫、信令和回调。

### 密钥与媒体

- 复用经过验证的原密钥协商和媒体加密实现，核实 DH 参数、随机数、公钥验证、指纹及协议层协商。
- 适配原通话引擎需要的连接信息和信令格式，实际验证双向音频、双向视频及原引擎支持的语音与视频切换。
- 先确认本仓库引擎支持的 P2P、ICE、反射器或中继协议，再选择兼容的服务及配置。
- 分别验证直接连接和强制中继。关闭 P2P 时检查实际选用路径符合隐私设置。
- 覆盖常见 NAT、不同网络、UDP 受限、网络切换及短暂断网，确认双方状态能够恢复或明确结束。
- 群通话所需的媒体服务器、参与者流、发布订阅和加密能力独立设计、验证和说明。

### 更新、后台与同步

- 将原客户端所需的呼叫状态和信令更新接入现有 typed 协议及分发流程。
- 明确实时信令、持久状态事件与差分重放的边界。处理重复、过期、丢失和重连，避免复活已结束呼叫。
- 新增协议字段和 operation 使用追加编号，保留既有字段及含义，检查旧客户端遇到新更新类型时的兼容策略。
- 检查事件编解码、事件游标、TL pts、差分分页、PostgreSQL 约束、outbox 及四组件消费者的兼容性。
- 实现前台、后台、锁屏和系统回收进程后的来电送达与通知。核实当前 Android 版本的前台服务、全屏来电和权限要求。
- 需要推送凭据、应用配置或外部服务时，列出具体配置文件、配置项及用途。设备验证区分系统回收和用户强行停止等场景，并记录实际结果。

### 存储与部署边界

- 当前支持的 LegacyOnly 和 PostgreSQL／四组件路径分别接入和回归。
- 迁移兼容现有账号、会话、TL 身份、聊天、消息、隐私设置、验证器和恢复码数据。
- 数据库结构变更采用明确的离线迁移步骤，并核对当前运行版本和读写者兼容性。
- 依照当前会话已有授权操作服务。需要新增公网端口、域名、推送凭据或外部资源时，给出具体需求及可审阅方案。
- 升级已获授权的测试服务前读取实际进程和监听配置，停机释放租约，备份数据、配置和加密密钥环，使用独立发布目录启动，检查健康和数据保留。
- 日志只记录排障所需状态、阶段和耗时，保护 Bearer、密码、通话密钥、完整敏感信令及真实用户数据。
